To run your Selenium tests in parallel across multiple machines and browsers, you can set up a Selenium Grid. Here's a step-by-step guide to help you configure it:

What is Selenium Grid ?
Selenium Grid allows you to run tests on different machines (nodes) and browsers in parallel by routing commands from a central Hub to remote Nodes.

Pre-requisites:
1. Java installed on all machines
2. Selenium Server JAR (or use Docker for easier setup)
3. Browsers and drivers (e.g., ChromeDriver, GeckoDriver) installed on each node
4. Network connectivity between Hub and Nodes

Docker-Based Selenium Grid (Recommended):
Step 1: Install Docker on all machines

Step 2: Use Docker Compose (on Hub machine)
 Create a docker-compose.yml as below:

version: "3"
services:
  selenium-hub:
    image: selenium/hub:4.16.1
    container_name: selenium-hub
    ports:
      - "4442:4442"
      - "4443:4443"
      - "4444:4444"
    environment:
      - GRID_MAX_SESSION=10
      - GRID_TIMEOUT=120 # higher value gives the driver more breathing room to bind the port during heavy parallel spikes.

  chrome-node:
    image: selenium/node-chrome:4.16.1
    shm_size: '2gb' # Size of shared memory; Increased size from 64MB to 2GB prevents the browser crashing in Docker
    depends_on:
      - selenium-hub
    environment:
      - SE_EVENT_BUS_HOST=selenium-hub
      - SE_EVENT_BUS_PUBLISH_PORT=4442 # Selenium v4 uses ports 4442 and 4443 for the internal message bus
      - SE_EVENT_BUS_SUBSCRIBE_PORT=4443
      - SE_NODE_MAX_SESSIONS=4 # Number of parallel Chrome tests
    ports:
      - "5555:5555" # Selenium Grid v4 requires the Hub to be able to talk back to the Node on its own port (usually 5555)

  firefox-node:
    image: selenium/node-firefox:4.16.1
    shm_size: '2gb'
    depends_on:
      - selenium-hub
    environment:
      - SE_EVENT_BUS_HOST=selenium-hub
      - SE_EVENT_BUS_PUBLISH_PORT=4442
      - SE_EVENT_BUS_SUBSCRIBE_PORT=4443
      - SE_NODE_MAX_SESSIONS=4 # Number of parallel Firefox tests
    ports:
      - "5556:5556"

Step 3: Start the grid -->Run "docker-compose -f /path/to/docker-compose.yml up -d" command and access Grid UI at http://localhost:4444/ui

Step 4: Test via Browser (The "Sanity" Check): 
Run "http://localhost:4444/wd/hub/status" in the browser
OR
From a Node machine(use "docker exec -it <node container_id/name> bash" command), try to access the Hub's status page via curl:
Bash>
curl http://<hub-ip-address>:4444/status

If you get a JSON response showing ready: true, your network path is clear. Please note to provide a hub-ip-address from vEthernet(WSL) network, neither "0.0.0.0" nor "localhost".

Step 5: TestNG + RemoteWebDriver Integration -->In your test base class
public class BaseTest {
    protected WebDriver driver;

    @Parameters({"browser"})
    @BeforeMethod
    public void setup(String browser) throws MalformedURLException {
        DesiredCapabilities caps = new DesiredCapabilities();
        if (browser.equalsIgnoreCase("chrome")) {
            caps.setBrowserName("chrome");
        } else if (browser.equalsIgnoreCase("firefox")) {
            caps.setBrowserName("firefox");
        }
        driver = new RemoteWebDriver(new URL("http://172.0.2.21:4444/wd/hub"), caps);//provide Selenium Hub's ip-address from vEthernet(WSL) network, neither "0.0.0.0" nor "localhost"
    }

    @AfterMethod
    public void tearDown() {
        if (driver != null) {
            driver.quit();
        }
    }
}

Step 6: An example TestNG XML for Parallel Browsers
<suite name="GridSuite" parallel="tests" thread-count="2">
    <test name="ChromeTests">
        <parameter name="browser" value="chrome"/>
        <classes>
            <class name="tests.LoginTest"/>
        </classes>
    </test>
    <test name="FirefoxTests">
        <parameter name="browser" value="firefox"/>
        <classes>
            <class name="tests.LoginTest"/>
        </classes>
    </test>
</suite>

Step 7: Jenkins Integration (CI/CD)
-Install Plugins --> Docker Pipeline, Maven Integration, HTML Publisher plugins and TestNG Results Plugin
-A Jenkinsfile example:
pipeline {
    agent any
	
    tools {
        // Ensure 'Maven3' and 'JDK17' match the names configured in Jenkins Global Tool Configuration
        maven 'Maven3'
        jdk 'JDK17'
    }

    stages {
        stage('Start Selenium Grid') {
            steps {
                sh 'docker-compose -f docker-compose.yml up -d'
            }
        }
	stage('Checkout') {
            steps {
                // Fetches code from your repository
                git branch: 'main', url: 'https://github.com/your-repo/test-automation.git'
            }
        }

        stage('Build & Test') {
            steps {
                // Using the -Pheadless Maven profile we created earlier
                // -DsuiteXmlFile allows you to swap suites if needed
                sh 'mvn clean test -Pheadless -DsuiteXmlFile=testng.xml'
            }
        }
        stage('Publish Results') {
            post {
                always {
                    	junit 'test-output/testng-results.xml'
			
			// Archive the ExtentReport so it's viewable in Jenkins
            		publishHTML(target: [
                		allowMissing: false,
                		alwaysLinkToLastBuild: true,
                		keepAll: true,
                		reportDir: 'reports',
                		reportFiles: 'index.html',
                		reportName: 'Extent Report'
            			])
            
            		// Capture TestNG results for the Jenkins trend graph
            		junit 'target/surefire-reports/*.xml'
                }
            }
        }
        stage('Stop Grid') {
            steps {
                sh 'docker-compose down'
            }
        }
    }//stages

}//pipeline

Notes: To run your Selenium Grid setup and automated tests using Jenkins, the Jenkinsfile should be placed in the root directory of your project repository — the same level as your pom.xml and docker-compose.yml. Jenkins uses the Jenkinsfile as a pipeline definition. When you configure a Jenkins job to use Pipeline from SCM (e.g., Git), it looks for the Jenkinsfile at the root by default.
